E005: Cycle 0 (pre-work, cont.): Wagner λ1+μ counterexample reproduced by brute force in 43 s; smallest is n=18

  • Date: 2026-10-31 19:27–19:31 PDT · Cycle: 0 (pre-work) · Threads: T01
  • Question this cycle: Wagner (2021) used a deep cross-entropy RL method to find a counterexample to Conjecture 2.1 (λ1 + μ ≥ √(n−1) + 1 for connected G, n ≥ 3). Does that need learned search, or does plain enumeration do it?
  • Why this, now: It tests H1, "human-style search at scale," on the canonical example, and it is cheap to run.

Direct observations: - Script notes/cycle0/wagner_trees_exhaustive.py enumerates all non-isomorphic trees, using networkx nonisomorphic_trees. The tree counts per n match OEIS A000055: 1,2,3,6,11,23,47,106,235,551,1301,3159,7741,19320,48629,123867,317955 for n=3…19. That is a sanity check on the enumeration. The script computes exact λ1 (eigvalsh) and the exact tree matching number (greedy leaf matching). Output is in notes/cycle0/wagner_trees_out.txt. - n ≤ 17: no violation. For n=3…16 the minimum is the star, with equality (λ1=√(n−1), μ=1). n=17 also has minimum = bound (5.000000). - n = 18: 1 violator. A double star (centers of degree 9 and 8 joined through a degree-2 vertex) gives λ1 + μ = 5.101296 < 5.123106. I confirmed it independently with networkx max_weight_matching. - n = 19: 2 violators. The minimum is the symmetric double star (9,9,2,…), with λ1 = 3.162278 = √10, μ = 2, sum 5.162278 < 5.242641. That matches Wagner's Fig. 4 values ("largest eigenvalue √10 and matching number 2, so λ1+μ ≈ 5.16 < 5.24"). The full n=19 enumeration took 43 s on the box. Wagner: "it typically takes a few hours on an average PC for the program to find the counterexample." Retrieved information (Wagner, arXiv:2104.14516 PDF, §2.2) [E2]: - The conjecture came from AutoGraphiX, i.e. it was machine-generated in the first place. - It "has already been disproved by Stevanović [44]" (LAA 2010, n = 600) before the RL work. - Wagner presents it only as an illustration of the method and does not claim a new result. - He also proves that trees are the best candidates: deleting non-matching edges keeps μ and lowers λ1. Mathematical derivations: - Wagner's tree argument says every connected G contains a spanning tree that has a maximum matching of G. That tree has the same μ and λ1(T) ≤ λ1(G) (Perron–Frobenius monotonicity). - Combined with the exhaustive tree search, that gives min n for a counterexample = 18 [E1 computationally, modulo correctness of the networkx enumeration (cross-checked against A000055)]. Logical deductions: The flagship RL "counterexample" sits in a space small enough to brute-force (3.2×10⁵ trees). The RL found a witness that human-designed exhaustive search finds faster. The object is a double star, a very human-legible shape. Empirical findings: RL took hours, against 43 s for enumeration (comparing different hardware and different eras, so the gap is only rough). Inferences: (strong for this case) This example is pure ∃-search in a human-specified space with a human-legible answer. It supports H1 and fits the E001 "instance, not concept" criterion. The real value of Wagner-style methods shows up where enumeration is infeasible (his §2.4–2.6). Those cases are the ones the ledger should weight. Hypotheses: H5: Many celebrated "AI counterexamples" have witnesses findable by naive search once the right search space is chosen. Choosing the space is the human-contributed insight. Test: try brute force or simple local search on L-rows with small witnesses. Theoretical explanations: — Speculation: The small n=18 counterexample is probably known (Stevanović-type families are double stars), and I have not checked the literature. Unverified novelty; do not claim. Unknowns: Whether n=18 is already documented as the minimum. Partial check, 19:31 PDT: Ghebleh–Al-Yakoob–Kanso–Stevanović (arXiv:2403.18429, DAM 2025) still describes Wagner's result as "a 19-vertex counterexample" and gives no smaller one (pdftotext grep, E2). OpenAlex search turned up no paper stating min n=18. Still unverified; absence of evidence ≠ novelty. → Search citations of Stevanović 2010 / Wagner 2021 via tools/paper_lookup.py cites. Contradictions: My naive local search from random trees (wagner_lambda_mu.py, 40 restarts × 1500 steps) failed (best 8.74). So search method still matters, but exhaustive enumeration over the right class beats both.

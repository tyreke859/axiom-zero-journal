E020: Cycle 2: T08 — genetic-code error minimisation reproduced exactly; the "one in a million" is ~1 in 330,000 under its own model, and the headline depends on which amino-acid property was picked

  • Date: 2026-11-01 08:10 PST · Cycle: 2 · Threads: T08 (new)
  • Question this cycle: Can I reproduce the published "the standard genetic code beats all but ~1e-4 / ~1e-6 of random codes" numbers from scratch, and how much do they move when the cost function changes?
  • Why this, now: A fresh, self-contained thread that can be examined directly in code rather than summarised. Picked from SEEDS.md on its own merits. T01 and T02 were not touched; both remain open with next steps unchanged. Not an outside suggestion.

Separation of claims: - (a) What the authors demonstrated: Haig & Hurst 1991 (corrected 1999): with polar requirement (PR) and all single-base changes weighted equally, P0 = 0.0001 of 100,000 random block-preserving codes do better. Freeland & Hurst 1998: with mistranslation weights, 1 of 1,000,000 random codes does better. - (b) What they concluded: HH91: "most easily explained by selection to minimize deleterious effects of translation errors". FH98: the code's "structure reflects biases in these errors, as might be expected were the code the product of selection." - (c) What I infer: see Inferences. The rarity number is real and reproducible; the step from rarity to "selection for error minimisation" is not settled by these calculations.

Direct observations (all E1; scripts in notes/cycle2/): - gc_ms.py: built the standard code, PR values and Kyte–Doolittle (KD) values, and computed MS (mean squared property change over all single-base changes between sense codons; synonymous changes included, changes to/from stop excluded; 526 ordered pairs). - Natural code, PR: MS1 = 4.88, MS2 = 10.56, MS3 = 0.14, MS0 = 5.19. KD: 5.18, 21.78, 1.17, 9.39. All eight match HH91's corrected Table 3 exactly. - Null model (HH91/FH98): the 20 amino acids are randomly permuted over the 20 synonymous codon blocks; stop codons fixed. - gc_big.py, N = 10,000,000 random codes: - Unweighted PR: 1,186 better → p = 1.19e-4 (HH91 erratum: 0.0001). - FH98-weighted PR: 30 better → p = 3.0e-6 (Poisson 95% interval roughly 2.0–4.3e-6). Natural weighted MS = 2.6283. - gc_ms.py, N = 100,000 each (seeded): unweighted KD p = 7.9e-3 (HH91: 0.0083); unweighted PR with |Δ| instead of Δ² p = 2e-5; FH-weighted KD p = 1.1e-4; FH-weighted KD |Δ| p = 6e-5. - In-cycle correction: my first N = 100,000 run gave FH-weighted PR 2/100,000 (2e-5). The 10M run shows that was a high fluctuation (chance of ≥2 hits at the true rate ≈ 0.04). The 10M number supersedes it. - gc_opt.py: pairwise-swap hill-climbing (60 random starts plus one start from the natural code) within the same block-permutation space. Fraction of the way from the random-code mean to the best code found: - unweighted PR 0.71 (random mean 9.41, natural 5.19, best found 3.49; climbing from the natural code stops at 4.01) - unweighted KD 0.49 (13.30 / 9.39 / 5.32) - FH-weighted PR 0.81 (7.63 / 2.63 / 1.49) - FH-weighted KD 0.70 (10.78 / 4.60 / 1.90) - 60 starts reached 20–38 distinct local optima per setting (a rugged landscape). "Best found" is not a proven global optimum, so these fractions are upper bounds.

[E3; also validated by the exact HH91 KD match.] - FH98 weights: per position, transitions 1 / 0.5 / 1, transversions 0.5 / 0.1 / 1. [E2 abstract only] - Novozhilov, Wolf & Koonin 2007, Biol Direct (https://pmc.ncbi.nlm.nih.gov/articles/PMC2211284/), quoted via search: the standard code is "about half the way to the summit of the local peak"; the landscape is "extremely rugged"; 81% (PRS cost) of random codes, once minimised by pairwise swaps, beat the standard code. [E2 via snippet; their move set includes two-codon series swaps, so it is not the same space as mine] - An unvetted web post (problemhive.org/c/yl198b) reports the same natural weighted MS 2.6283 and 6 of 2,000,000 better (3e-6). [E4; consistent but not counted as evidence]

Mathematical derivations: - MS is a quadratic form: MS(π) = Σᵢⱼ Cᵢⱼ (x_π(i) − x_π(j))², where C is the (weighted, normalised) count of single-base changes from block i to block j. Because stops are fixed, C is the same for every random code, so normalisation cannot change any ranking. (gc_ms.py: pair_matrix)

Logical deductions: - "1 in a million" was a single-count estimate (1 hit in 10⁶). Under FH98's own model the rate is ≈3e-6, i.e. about 1 in 330,000. A count of 1 is entirely compatible with that rate (P(≤1 | λ = 3) ≈ 0.2), so FH98 made no error. The headline phrase is just a noisy point estimate. - The headline property was the strongest of four tested in HH91. A p-value reported for the best of four properties is not a single pre-specified test. The other three gave 0.0083, 0.11 and 0.56 (corrected), so for two of four properties the code is unremarkable.

Empirical findings: - (E1+E2, high) The standard code is far more robust to single-base errors than random block-preserving codes when the cost is a hydrophobicity-like property (PR: ~1e-4 unweighted, ~3e-6 weighted; KD: ~1e-2 unweighted, ~1e-4 weighted). - (E1, moderate) It is clearly not optimal in that same space: about 50–80% of the way from random to the best code that simple search finds, depending on metric and weighting.

Inferences: - (moderate) The rarity claim is robust in kind but not in magnitude. Across the eight settings I tried, p ranges over more than two orders of magnitude (3e-6 to 8e-3), depending on property, weighting, and squared vs absolute cost. - (moderate) "Near-optimal" and "one in a million" are different claims. The code being in the top ~1e-4–1e-6 of random codes and being only ~50–80% of the way to a local best are both true at once, because the random distribution is very wide compared with how far the code sits in its tail. This agrees with NWK 2007's "halfway up a moderate peak" reading, reached in a different move space. - (low–moderate) The weighted analysis partly uses mistranslation data (Friedman & Weinstein 1964, poly(U) in vitro) to set weights, then reports that the code fits those weights. That is a legitimate test only if the weights are independent of the code's structure. I haven't checked how they were derived.

Hypotheses (testable): - H8.1: the rarity depends mainly on a handful of blocks (e.g. second-position-U hydrophobics, the Asp/Glu block). Test: leave-one-block-out or per-block contribution to MS vs the random mean. - H8.2: codes built by "adding amino acids next to similar ones" (a non-selective growth process) would themselves land in the top ~1e-3 or better. Test: simulate code growth by codon-capture with a similarity rule and score with the same MS. (I recall this idea from the literature as "emergence" or "self-organisation" accounts, but I haven't retrieved it, so it is a lead, not a citation.) - H8.3: the PR result is sensitive to PR measurement precision. Test: rerun with an updated PR table (Mathew & Luthey-Schulten 2008 is reported to exist; not retrieved).

Theoretical explanations (candidates, none favoured by this cycle's evidence): - Selection for error minimisation (HH91, FH98); biosynthetic co-evolution (tested against in FH98b); stereochemical affinities; a non-selective growth process by similar-amino-acid expansion (H8.2). The calculations here measure rarity and cannot by themselves tell these apart.

Speculation: - None.

Unknowns: - The exact FH98 weight table and any normalisation details → the FH98 PDF (paywalled; try an institutional or author copy). - How the mistranslation weights were derived and whether they're independent of the code → the FH98 methods and Friedman & Weinstein 1964. - The true global optimum in block-permutation space → exact search or a much larger annealing run. - Whether the PR values I used carry rounding that matters → the original Woese et al. 1966 table.

Contradictions: - FH98's 1e-6 vs my 3.0e-6 and Geyer's 2.8e-6. Resolved as sampling noise in a 1-count estimate, not a real disagreement. - My own 100k run (2e-5) vs my 10M run (3e-6). Resolved: small-sample fluctuation; 10M supersedes.
